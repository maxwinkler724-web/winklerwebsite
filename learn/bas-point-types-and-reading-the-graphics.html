BAS Point Types and Reading the Graphics

Last updated: 2026-10-16

Part of the Commercial Cooling Guide

A building automation screen is a picture of a points list. Know the four basic point types, and you can read almost any graphic and the data behind it.

The four basic types

A controls maker's documentation uses the standard BACnet vocabulary:

  • Analog input (AI): a measured number, such as a temperature, pressure or humidity. Read only.
  • Binary input (BI): an on/off or yes/no state, such as a status, alarm or filter flag. Read only.
  • Analog output (AO): a number the controller sends out, such as a valve position or fan speed command.
  • Binary output (BO): an on/off command, such as start/stop.

Add virtual points, called analog value (AV) or binary value (BV). A small controls vendor explains that they are software variables, with no physical wiring. They usually carry setpoints, calculated values, occupancy commands or filter flags rather than driving hardware. In one maker's points list, analog values and binary values are the read/write ones used for setpoints and commands, while the inputs are read only. For protocol background see BACnet, Modbus and LonWorks in Plain English.

Reading a points list

An integration points list is the written map behind the graphics. One manufacturer's list for a rooftop unit controller is organized by object type, then by identifier and name. Columns include name, description, whether the point exists on every configuration, read or write access, units or states, valid range and the Modbus address. That list explains that not every point appears on every unit because points depend on the equipment's configuration, such as economizer or heat options. So if a point on the template is missing from your unit, that is not necessarily a fault.

Reading the suffixes

The same list uses name endings that tell how to treat a value. A few examples from that one manufacturer: a status is a read-only value the controller is using, a local value comes from a sensor connected to the controller, a setpoint is a target, and a command or request is a write. An active value is the result after the controller arbitrates between the building system and local sources. It also lists an arbitrator view showing competing sources. Other makers use different names. The principle is the useful part: the number you wrote is not always the number in use.

Overrides and priority

When you write a value from a graphic, it may sit at a priority level. A BACnet point supports a priority array, and the controls vendor notes virtual points support it. A manual override at a high priority can quietly beat the schedule. Releasing it returns control to automatic. Commissioning guides ask testers to confirm that releasing an override does return the point to automatic control. Always release your overrides and note any you find.

What a good graphic shows

A university's guideline for building automation graphics describes a graphic that supports text, live values, animation, logs, graphs, schedules and links between screens, with schedules and setpoints adjusted by sliders and calendars. It also sets performance expectations, such as a graphic with a certain number of live points appearing in a few seconds. That is one owner's specification, but the lesson holds: the graphic should show the status, command and alarm together.

Reading a graphic carefully

  • Status vs. command. A fan command of on and a status of off means something is wrong. Check both.
  • Units and scaling. Confirm the units, since they can be configured wrong.
  • Sensor trust. A flat line or a number that never changes may be a failed sensor, a stale value or a communication loss. See BAS Sensor Types, Calibration Drift and Setpoint Habits.
  • Color is a convention. Do not assume red means alarm on every system. Use the legend.
  • The picture is not the pipe. Graphics are simplified. Verify field conditions before acting.

Safe habits

  • Treat writes as real commands on real equipment. Know what will start or stop before you click.
  • Never use the BAS to defeat a safety. Hardwired safeties must stay hardwired.
  • Record what you changed and why.
